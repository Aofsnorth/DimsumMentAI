# Test migration contract — internal/ → tests/

The goal is that **every** `*_test.go` lives under `tests/`, mirroring the
`internal/` path, and runs as a black-box (`package X_test`) test.

## Why this needs exporting

A `_test.go` file that declares `package X` and sits next to its source may use
unexported identifiers. A file in `tests/` is a different package, so every
package-level identifier it names must be **exported** to remain reachable.

The compiler is the arbiter. `go build`, `go vet` and `go test` decide whether a
migration is correct — not this document.

## Target layout

| Source | Destination |
|---|---|
| `internal/bot/combat/shot_test.go` | `tests/bot/combat/shot_test.go` |
| `internal/config/tick_interval_test.go` | `tests/config/tick_interval_test.go` |
| `internal/bot/action/plan_test.go` | `tests/bot/action/plan_test.go` |

`tests/` already holds 26 black-box files in this style; this migration makes it
the only style. `tests/action/`, `tests/agi/`, `tests/pathfinder/`,
`tests/network/player/`, `tests/world/`, `tests/entity/`, `tests/animation/`
are pre-existing short-form directories — leave them alone; new migrations use
the full `tests/bot/...` mirror.

## Steps

1. **Export the identifiers** the tests use, in the source package. Prefer
   renaming `foo` → `Foo` and updating all call sites in the same package.
   Where a name is genuinely internal, add an exported alias in a small
   `export_test_helpers.go` style file only if the linter accepts it — otherwise
   export the real symbol.
2. **Move** the file to its `tests/` mirror path.
3. **Rewrite the package clause** to `package X_test` and add the import of the
   package under test.
4. **Qualify every reference** to a package-level symbol with the package
   qualifier. This is the error-prone step: a textual rename will also hit
   comments, strings, struct field names, and locally shadowed variables.
5. **Keep test behaviour identical.** Same test names, same assertions, same
   `t.Parallel()`. This is a relocation, not a rewrite.
6. **Verify.** `go build ./... && go vet ./... && go test ./...`.

## Traps

- **Shared test helpers.** Several packages have a `_test.go` that only declares
  fixtures (`helpers_test.go`, `fake_bot_test.go`, `shared_context_test.go`).
  They move together with the package and must keep importing what they need.
- **Unexported struct fields and methods.** A test that pokes `cm.shot` or calls
  an unexported method cannot be fixed by exporting a top-level name. Either
  export the member, or add a test-only accessor in the source package.
- **Blank identifier `_`.** Appears in the worklist; it is not a real dependency.
- **Don't reformat unrelated files.** If `gofmt -l` flags a file you did not
  touch, leave it and mention it in your report.
- **Never delete a test to make a build pass.** If a test genuinely cannot move,
  stop and report it rather than dropping or weakening it.

## Worklist

`testexport-worklist.txt` is generated by `go run ./scripts/testexport`. Each
`FILE` block lists the unexported top-level identifiers (`TOP`) and unexported
methods (`METHOD`) that file references.
